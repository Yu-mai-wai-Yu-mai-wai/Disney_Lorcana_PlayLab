1. BACKGROUND & PROBLEM STATEMENT

ปัญหาและความท้าทายของ Digital TCG เดิม

ช่องว่างทางวิศวกรรมที่นำไปสู่การออกแบบ Disney Lorcana PlayLab Cloud

<100ms Target Latency

💸 1. High Server Cost & Overhead

  • ระบบเกมการ์ดทั่วไปใช้ Dedicated VM / EC2 ทำงาน 24/7
  • เกิดต้นทุน Idle Compute สูงตลอดเวลา แม้ไม่มีผู้เล่นใช้งาน
  • ไม่ตอบโจทย์งบประมาณสถานศึกษาและ AWS Free Tier

⏱️ 2. High Latency & Polling Bottlenecks

  • การส่งข้อมูลด้วย HTTP Polling ส่งผลให้เกิดความหน่วงสูง (>500ms)
  • สถานะการขยับการ์ดและผลทอยลูกเต๋าไม่ซิงค์แบบเรียลไทม์
  • เกิด Race Condition เมื่อผู้เล่น 2 ฝั่งแย่งหยิบการ์ดพร้อมกัน

🎴 3. Flat & Unengaging 2D UI

  • เว็บการ์ดส่วนใหญ่ใช้ UI 2 มิติแบนราบ ขาดมิติทางกายภาพ
  • ไม่มีแอนิเมชันเปิดซอง Booster Pack หรือส่องการ์ด Foil 3 มิติ
  • ขาดระบบตรวจเด็คการ์ดอัตโนมัติตามกฎทางการ (Max 4 Copies / 60 Cards)
💡
The Solution: ผสาน AWS Serverless Microservices ร่วมกับ Elastic Multi-AZ IaaS (Auto Scaling) เพื่อรองรับการเล่นการ์ดแบบ Sub-50ms ทรงพลัง สวยงาม และคุมงบประมาณต่ำกว่า $1–$3 ตลอดทั้งเทอม ($50 Learner Lab Guardrail)

4. REAL-TIME ENGINE & WEBSOCKETS

ระบบซิงค์กระดาน 2 ผู้เล่น & WebSockets

การสื่อสารสองทิศทางความหน่วงต่ำกว่า 50ms พร้อมระบบกู้คืนสถานะหลุดการเชื่อมต่อ

<50ms Sync Latency

🕹️ การทำงานของกระดาน Lorcana Board

  • โซนการเล่นครบวงจร: Play Area, Inkwell, Hand, Deck, Discard Pile, และ Lore Tracker (0–20 แต้ม)
  • Card Mechanics: รองรับการลากวาง (Drag & Drop), หมุนการ์ดสถานะ Ready (0°) และ Exert (90°)
  • Optimistic Updates: หน้าจอผู้เล่นขยับทันทีใน 0ms ก่อนส่ง Event ผ่าน WebSocket ไปยังคู่ต่อสู้
  • Turn & Pass Priority: ซิงค์ลำดับเทิร์นและแจ้งเตือนความสามารถการ์ด (Ability Notification Banner)

🔌 WebSocket Resiliency Architecture

  • Dual Protocol Support: รองรับทั้ง AWS API Gateway WebSocket API และ Native `ws` บน Node.js EC2
  • Sub-50ms Relay: ส่งข้อมูลเฉพาะ Delta Event เช่น `CARD_MOVED`, `INK_ADDED`, `LORE_CHANGED`
  • 60s Rejoin Grace Period: หากผู้เล่นเน็ตหลุด ระบบจะสงวนสถานะบน DynamoDB ไว้ 60 วินาทีให้กลับมา Reconnect ได้ทันทีโดยการ์ดไม่หาย
  • Opponent Disconnect Notice: แจ้งเตือนสถานะเมื่ออีกฝ่ายขาดการเชื่อมต่ออย่างชัดเจน
Matchmaking State Lifecycle: CREATE_ROOM ➔ JOIN_ROOM ➔ START_MATCH ➔ SYNC_ACTION ➔ LEAVE_ROOM / GAME_OVER

5. BACKEND & SECURITY ARCHITECTURE

ไมโครเซอร์วิสและความปลอดภัยตามมาตรฐาน OWASP

การออกแบบ Backend API ปลอดภัย ป้องกัน Brute-force และควบคุมอายุข้อมูลอัตโนมัติ

OWASP A07 Hardened

🔐 1. Authentication Service

  • รหัสผ่านแฮชด้วย bcrypt (10 Salt Rounds) ปลอดภัยสูง
  • ออกสิทธิ์การใช้งานผ่าน JWT Token (HS256)
  • In-Memory Rate Limiting: บล็อก IP/User ที่ล็อกอินผิดเกิน 5 ครั้ง นาน 5 นาที (ป้องกัน Brute Force Attack)

🃏 2. Deck Management Service

  • RESTful API Endpoints: `POST /decks`, `GET /decks`, `DELETE /decks/{id}`
  • จัดเก็บเด็คการ์ดลง Amazon DynamoDB (`DecksTable`)
  • ตรวจสอบความถูกต้องของ JSON Payload และขนาดเด็คก่อนบันทึก

🧹 3. Room & TTL Cleanup

  • เก็บห้องเล่นบน DynamoDB (`LorcanaRoomStateV2`)
  • ตั้งค่า DynamoDB TTL (Time-To-Live 2 ชั่วโมง) ลบห้องที่เล่นเสร็จแล้วอัตโนมัติฟรี ไม่เปลือง Storage
  • เชื่อมโยง Amazon SQS คิววิเคราะห์เด็คแบบ Asynchronous
IAM Least Privilege & IMDSv2: ระบบรันภายใต้สิทธิ์ของ LabRole ผ่าน AWS Instance Metadata Service v2 (IMDSv2) โดย ไม่มีการฮาร์ดโค้ด AWS Access Key หรือ Secret Key ลงในโค้ดหรือ Docker Image แม้แต่บรรทัดเดียว

6. ARCHITECTURAL EVOLUTION

วิวัฒนาการสู่ Lean Multi-AZ Auto Scaling

ยกระดับจาก S3 Static สู่ Containerized Elastic IaaS เพื่อตอบโจทย์วิชา Cloud เต็มรูปแบบ

Auto Scale CPU > 60%

❌ เหตุผลที่เปลี่ยนจาก S3 Static Hosting

  • ไม่มี Compute Engine: S3 ทำได้เพียงเก็บไฟล์ ไม่สามารถรัน Container หรือ Node.js Server-side logic
  • ไม่ตอบโจทย์เกณฑ์ IaaS: ไม่สามารถแสดงทักษะด้าน Custom VPC Subnetting, Security Group Layering, Load Balancer, และ Auto Scaling Group

✅ สถาปัตยกรรมใหม่: Lean Multi-AZ ASG

  • Multi-AZ VPC (`10.0.0.0/16`): แบ่ง Subnet ข้าม us-east-1a และ us-east-1b รองรับกรณี AZ ล่ม (Fault Tolerance)
  • Application Load Balancer: กระจายโหลด HTTP/WS พร้อมเช็ก GET /health ทุก 15s
  • Auto Scaling Group: สเกล 1 ➔ 2 ➔ 3 อินสแตนซ์อัตโนมัติเมื่อ CPU > 60%
  • Multi-Stage Docker: Nginx Reverse Proxy (Port 80) + Node.js (Port 3001) แรม <150MB
